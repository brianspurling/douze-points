# UK LADs Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a fourth menu option, **UK**, that swaps the map to a UK Local Authority Districts (LAD) topojson and runs the existing 25-round game (Eurovision shell unchanged) against ~360 LADs across England, Scotland, Wales, and Northern Ireland. Coat-of-arms PNGs replace flag emoji in the UI; home-nation-emoji-prefixed full names replace them in share text.

**Architecture:** All JS/CSS/HTML changes stay in the single `index.html`. Builds on the region-descriptor infrastructure shipped with USA mode — adds one entry to `SOURCES`, one entry to `REGIONS`, one branch to `flagHTML` / `flagShareToken`, and one menu item. The single piece of new internal scaffolding is a `featureName(f)` helper that abstracts the property key (`name` for world-atlas / us-atlas, `LAD24NM` for the ONS LAD topojson). Coat-of-arms PNGs are committed to the existing `flags/` directory; missing ones degrade gracefully via `onerror`.

**Tech Stack:** Vanilla HTML/CSS/JS, D3 v7, topojson-client. New data source: ONS LAD boundaries (Dec 2024 release or later — exact URL resolved in Task 1). No build step. No test framework — verification is manual via the browser preview tools (`preview_start`, `preview_resize`, `preview_screenshot`, `preview_snapshot`, `preview_console_logs`).

**Spec:** [docs/superpowers/specs/2026-05-24-uk-lads-design.md](../specs/2026-05-24-uk-lads-design.md)

### Task 5: Source coat-of-arms PNGs

**Files:**

- Create: `flags/uk-<gss>.png` (~360 files)

**Goal:** Populate the `flags/uk-*.png` library so sidebar slots render the council coat-of-arms. Best-effort: missing or wrong-image scrapes fall back to the empty slot via `onerror`.

- [ ] **Step 1: Write the scrape script.**

`scripts/fetch-uk-coa.mjs`:

```js
// Run: node scripts/fetch-uk-coa.mjs
// Reads data/uk-lads.json, for each LAD hits Wikipedia page summary API,
// downloads the lead image, resizes to 160px wide, saves as flags/uk-<gss>.png.
// Requires: npm i -g sharp node-fetch (or use npx).
import { readFileSync, existsSync, writeFileSync } from 'node:fs';
import sharp from 'sharp';
import { feature } from 'topojson-client';

const NAME_KEY = 'LAD24NM';  // <-- match Task 1 Step 3
const CODE_KEY = 'LAD24CD';

const topo = JSON.parse(readFileSync('data/uk-lads.json', 'utf8'));
const objKey = Object.keys(topo.objects)[0];
const lads = feature(topo, topo.objects[objKey]).features.map(f => ({
  name: f.properties[NAME_KEY],
  code: f.properties[CODE_KEY],
}));

const failures = [];

for (const { name, code } of lads) {
  const out = `flags/uk-${code.toLowerCase()}.png`;
  if (existsSync(out)) { console.log(`skip ${out}`); continue; }

  try {
    const summaryUrl = `https://en.wikipedia.org/api/rest_v1/page/summary/${encodeURIComponent(name)}`;
    const summary = await fetch(summaryUrl).then(r => r.json());
    const imgUrl = summary?.originalimage?.source || summary?.thumbnail?.source;
    if (!imgUrl) throw new Error('no image in summary');

    const buf = Buffer.from(await fetch(imgUrl).then(r => r.arrayBuffer()));
    await sharp(buf).resize({ width: 160 }).png().toFile(out);
    console.log(`ok   ${out}  (${name})`);
  } catch (e) {
    console.log(`FAIL ${name}: ${e.message}`);
    failures.push({ name, code, error: e.message });
  }
  await new Promise(r => setTimeout(r, 150));  // be polite
}

writeFileSync('scripts/fetch-uk-coa.failures.json', JSON.stringify(failures, null, 2));
console.log(`\n${failures.length} failures written to scripts/fetch-uk-coa.failures.json`);
```
